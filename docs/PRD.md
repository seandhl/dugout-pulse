# DUGOUT PULSE PRD

- 작성일: 2026-11-03 (Asia/Seoul), 버전: 1.0
- 상태: 구현·검수 범위 기준. 앱 구현, 데이터 승인, 출시 완료를 뜻하지 않는다.
- 대상: 한국어 KBO 팬을 위한 모바일 우선 기록 탐색 서비스.
- 우선 규칙: [AGENTS.md](../AGENTS.md), [로드맵](ROADMAP.md), [ADR](DECISIONS.md). 이 문서는 P0 산출물이며 P1~P5 순서를 건너뛰지 않는다.

## 1. 제품 목적과 경계

최근 경기 기록의 변화를 타자·선발·불펜별로 설명하고, 비교 가능한 범위와 불확실성을 함께 보여준다. 대부분의 열람은 로그인 없이 제공한다. 일반 회원가입, 개인화 계정은 MVP에 없다. 관리자만 별도 인증·권한이 필요하다.

화면 공통 문구:

> DUGOUT PULSE의 ‘기세’는 최근 기록을 역할별로 가공한 설명용 지표입니다. 경기 결과나 미래 성적을 예측하지 않으며, 공식 KBO 통계 또는 KBO가 인증한 지표가 아닙니다.

데이터 공급 계약·승인 전에는 **데모 모드만 허용**한다. 가상 선수·팀·경기 식별자를 사용하고 모든 데이터 화면과 수치 카드에 `DEMO · 가상 데이터`를 표시한다. 현재 외부 데이터 수집·패키지 설치·배포는 이번 문서 작업 범위가 아니다. 실제 선수 기록처럼 보이는 임의 수치, 무허가 크롤링, 내부 API 분석, 접근 제한 우회, 무단 사진·로고 사용을 금지한다.

## 2. 공통 데이터와 필터 계약

### 공개 데이터 최소 계약 (P2에서 스키마·검증기 확정)

| 객체 | 필수 정보·규칙 |
| --- | --- |
| 배치/출처 | schemaVersion, batchId, sourceId, 출처명, 안전한 공개 참조, asOf(시간대 포함), importedAt, demo, 권리 검토 상태·안전한 증빙 참조, 공개 허용 필드 목록 |
| 선수·팀 | 안정 ID, 표시명, 시즌별 소속 이력·효력일, 역할. DEMO는 가상임을 명시. 이름 중복은 ID로 구분 |
| 기록 | 선수 ID, 경기 ID·일자, 팀 ID, 시즌, 대회, 역할, 원천 값, sourceId/batchId, asOf, demo, 표본 단위·크기 |
| 등록 | 선수 ID, 시즌, 등록 상태, 기준일·효력일, 출처. unknown과 미등록을 구분 |
| 가공 결과 | 입력 참조, 계산 버전, 역할, 기간 시작·끝, 기준일, 최소 표본, 실제 표본, 결측·산출 상태, demo, 원천 출처 집합 |

공개 응답은 허용 목록으로 만든다. 원본 파일, 내부 권리 증빙, 관리자 정보, 자격증명은 보내지 않는다. 필수 메타데이터 누락·음수 카운트·불가능한 분모·중복 경기 키·알 수 없는 참조·범위 밖 날짜는 게시 전에 거부한다. null은 0이 아니다. 비율은 합산 분자/분모로 재계산하며 단순 경기별 평균을 사용하지 않는다. 투구 이닝은 아웃 수 정수로 저장하고 1아웃은 `0⅓이닝`으로 표시해 소수와 혼동하지 않는다.

수치 카드에는 시즌·대회·기간·표본·as-of·DEMO를 표시하고, 출처 버튼으로 해당 값의 원천과 계산 버전에 접근한다. 한 카드가 여러 출처를 사용하면 모두 연결한다. as-of는 업로드 시각과 구분하며 한국시간으로 표시한다. 배치가 다른 수치를 섞어 최신인 것처럼 표현하지 않는다. 마지막 유효 배치를 표시하는 경우 실제 as-of와 갱신 실패를 함께 표시한다.

### 시즌·대회·팀·선수 범위

- 시즌과 대회(정규시즌/포스트시즌)는 전 화면 공통 조건이다. 기본값은 fixture에 존재하는 가장 최근 시즌·정규시즌이며 오늘 날짜를 데이터 기준일로 대체하지 않는다.
- ‘현재 등록’: 선택 시즌의 등록 스냅샷 기준일에 1군 등록이 확인된 선수. 과거 시즌은 `기준일 등록`으로 표기한다. 스냅샷이 없으면 `등록 정보 없음`이며 출전 이력으로 등록을 추정하지 않는다.
- ‘시즌 출전’: 선택 시즌·대회에서 1경기 이상 출전한 선수. 등록 여부와 독립이다. 기본 목록은 시즌 출전, 등록 필터는 별도 선택이다. 등록됐으나 미출전인 선수도 등록 목록·상세에 나타나며 기록은 빈 상태다.
- 팀 필터는 목록·랭킹·비교에서 **해당 팀 소속으로 기록한 경기만** 집계한다. `전체 팀`은 시즌 합계다. 등록 목록의 팀은 등록 스냅샷 소속이다. 이적 선수 상세에 이 차이를 설명한다.
- 역할은 타자/선발/불펜 탭으로 선택한다. 선발/구원은 경기별 등판 역할로 구분하고 혼합 역할 선수는 별도 집계한다. 서로 다른 역할 점수를 합산하지 않는다.
- 필터는 URL에 보존해 새로고침·뒤로 가기·공유 시 재현한다. 시즌 변경으로 팀·선수 조건이 무효가 되면 전체 팀으로 되돌리고 사유를 알린다. 비교 선수는 조건에서 제외되면 제거 사실을 알린다. 유효하지 않은 쿼리는 안전한 기본값과 안내로 처리한다.

## 3. IA와 화면별 계약

경로는 구현 계약안이며 특정 프레임워크 채택을 의미하지 않는다. 헤더는 홈/선수 검색/랭킹/비교/소개, 관리자는 별도 진입으로 제공한다.

| 화면·경로 | 필수 구성·행동 | 로딩 | 빈 상태 | 오류·오프라인 |
| --- | --- | --- | --- | --- |
| 홈 `/` | DEMO 안내, 공통 필터, 역할별 상위 3명, 검색 진입, 데이터 기준일, 방법론 링크 | 카드 스켈레톤·진행 안내 | 산출 가능 선수 없음·조건 변경 | 재시도, 마지막 유효 배치가 있으면 시각과 갱신 실패 표시 |
| 선수 검색 `/players` | 이름 검색, 팀·역할·등록/시즌 출전 필터, 20명씩 더 보기, 이름순 기본 정렬 | 입력 유지·결과 영역 로딩 | 검색 결과 없음·필터 초기화 | 검색어 유지·재시도; 저장된 데이터 없으면 오프라인 안내 |
| 선수 상세 `/players/:id` | 선수·역할·등록 기준일, 기세·필수 기록·그래프·경기표·출처·비교 담기 | 레이아웃 유지 | 미출전/기간 내 기록 없음/역할 기록 없음 구분 | 없는 ID는 찾을 수 없음, 데이터 실패는 재시도·검색 복귀 |
| 랭킹 `/rankings` | 역할별 기세 내림차순, 최소 표본·대상·동률 기준, 순위·표본·변화·선수 링크 | 표 스켈레톤 | 산출 가능 선수 없음; 부족 표본 목록 별도 | 조건 유지·재시도·마지막 배치 표시 |
| 선수 비교 `/compare` | 같은 역할 최대 2명, 동일 조건 요약·나란한 수치·동일 축 그래프·출처 | 두 영역 상태 표시 | 0명: 선택 안내, 1명: 두 번째 선택 안내 | 한 선수 실패 시 다른 선수 유지·부분 오류 재시도 |
| 소개/출처 `/about` | 목적·비예측 문구·산식 버전·역할별 윈도·최소 표본·데이터 목록·권리·연락/법적 표시 | 문서 로딩 안내 | 출처 미등록 시 데모 정책 안내 | 재시도·정적 기본 안내 제공 |
| 관리자 `/admin` | 별도 인증, 배치 목록·검증 결과·미리보기·게시·이전 배치 복구·감사 이력 | 인증 확인 중 콘텐츠 숨김 | 게시 배치 없음·입력 안내 | 미인증 로그인 안내, 권한 없음 접근 거부, 실패 시 기존 공개 배치 유지 |

공통: 키보드 조작, 명시적 라벨·초점 표시, 상태 메시지 읽기 지원, 색 외에 텍스트로 상승/하락·오류 구분. 360px 화면에서 페이지 전체 가로 스크롤 없이 동작한다(경기표는 이름 있는 독립 스크롤 영역 허용). 그래프와 동일 값의 표를 제공한다. 오프라인은 연결 실패 안내와 재시도를 제공하며 캐시나 오프라인 쓰기 큐는 MVP에 필수 아님. 캐시가 없으면 데이터를 보여주는 것처럼 꾸미지 않는다.

## 4. 역할별 필수 정보와 기세

모든 역할에 시즌 합계와 최근 구간을 구분한다. 아래 최근 구간은 **PRD 제안**으로 P3 ADR에서 확정해야 한다. 산식·가중치·정규화·최소 표본이 승인되기 전에는 점수를 생성하지 않고 `모델 미확정`을 표시한다. 승인 후 0~100의 역할 내 점수로 표현하되 다른 역할과 비교하지 않는다. 과거 시점 점수에는 그 시점까지의 데이터만 사용한다.

| 역할 | 필수 숫자 | 필수 그래프·경기표 | 필수 카드 |
| --- | --- | --- | --- |
| 타자 | G, PA, AB, H, 2B, 3B, HR, BB, HBP, SO, SF, AVG, OBP, SLG, OPS. AVG=H/AB, OBP=(H+BB+HBP)/(AB+BB+HBP+SF), SLG=총루타/AB, OPS=OBP+SLG | 최근 10개 출전 경기의 경기별 PA·안타·홈런과 최근 구간 OPS 추이; 최근 경기별 원천 카운트 표 | 역할 기세·이전 게시 대비 기세 변화량, 최근/시즌 OPS·PA, 마지막 출전 후 경과일·표본 상태 |
| 선발 | GS, 아웃 수/이닝, BF, H, HR, BB, HBP, SO, ER, ERA, WHIP, K/9, BB/9. ERA=27×ER/아웃, WHIP=3×(H+BB)/아웃, K/9=27×SO/아웃, BB/9=27×BB/아웃 | 최근 5회 선발의 이닝·자책점·탈삼진과 구간 ERA 추이; 등판별 표 | 선발 기세·변화, 최근/시즌 ERA·WHIP·이닝, 마지막 선발 이후 경과일 |
| 불펜 | 구원 G, 아웃 수/이닝, BF, H, HR, BB, HBP, SO, ER, ERA, WHIP, K/9, BB/9, 최근 7일 등판 수·이닝, 연속 등판일 수 | 최근 10회 구원의 이닝·자책점, 최근 14일 날짜별 등판·아웃 수; 등판별 표 | 불펜 기세·변화, 최근/시즌 ERA·WHIP, 최근 사용량·마지막 등판 후 경과일 |

총루타=1B+2×2B+3×3B+4×HR, 1B=H−2B−3B−HR. 분모 0은 `— · 계산 불가`로 표기한다. 비율은 소수 셋째 자리(AVG/OBP/SLG/OPS), ERA/WHIP/K9/BB9는 소수 둘째 자리로 표시하며 정렬은 반올림 전 값으로 한다. 표본 크기는 PA/등판 수/아웃 수처럼 단위를 함께 표시한다.

- 기세 카드는 점수, 기준일, 구간, 표본/최소 표본, 모델 버전, 기여 요인 최대 3개와 계산 설명을 제공한다. 기여 요인은 원천 수치로 검증 가능해야 한다.
- 표본 미달은 `표본 부족`, 필수 값 결측은 `데이터 부족`으로 점수·순위·점수 변화 산출에서 제외한다. 원천 기록은 공개 가능한 범위에서 계속 보여준다.
- 기세 변화량은 같은 선수·시즌·대회·역할·N·모델 버전의 이전 순위 적격 게시 점수 대비다. 이전 자료가 없으면 `비교 불가`다. 모델 내부 이동 창 점수차는 최신 역할 출전 하나를 제외한 N출전 대비로 창이 중첩한다. 별도 용어·툴팁으로 설명하며 비중첩 이전 창으로 해석하지 않는다(ADR-032). 임의 보간과 0점 대체를 금지한다.
- 휴식은 `마지막 출전 후 N일(데이터 기준일 기준)`로 표현한다. 경기 일정이 없으면 결장 경기 수를 계산하지 않으며, 이유가 확인되지 않은 상태를 부상으로 표현하지 않는다. 불펜 사용량은 피로·부상 확률로 해석하지 않는다.
- 동점은 동일 순위(1,1,3), 표시 순서는 안정 ID 오름차순이다. 모델 버전이 다른 결과는 같은 순위표·변화·비교에 혼합하지 않는다.
- P3 완료 조건: 세 모델의 산식·가중치·윈도·최소 표본·결측 정책·설명 템플릿을 ADR에 채택하고 동일 입력 재현, 경계값, 역할 전환, 휴식, 미래 데이터 비참조 테스트를 통과한다. 미결정 상태로 P4 기세 기능 완료를 선언할 수 없다.

## 5. 주요 사용자 흐름

1. 홈 → DEMO·기준일 확인 → 역할 선택 → 선수 카드 → 상세 → 최근 기록·표본 확인 → 출처/계산 설명. 홈 카드와 상세는 동일 조건·배치를 유지한다.
2. 검색 → 이름·팀·시즌 출전/등록 필터 → 선수 선택 → 상세. 결과가 없으면 조건 초기화, 등록 정보가 없으면 정보 없음 안내를 제공한다.
3. 랭킹 → 시즌·대회·팀·역할 선택 → 순위 근거 확인 → 두 선수 비교 담기 → 비교. 다른 역할 추가는 거부하고 역할 전환 안내를 제공한다. 세 번째 선수는 기존 선수 제거를 요청한다.
4. 비교 URL 공유 → 로그인 없이 동일 선수·필터 복원. 삭제/비공개/유효하지 않은 선수는 이름이나 내부 정보 노출 없이 선택 불가 상태와 재선택 안내를 제공한다.
5. 관리자 인증 → 권한 확인 → 승인 형식 파일 입력 → 서버 검증 → 공개 필드·DEMO·출처 미리보기 → 명시적 게시 → 공개 배치 교체 → 필요 시 이전 유효 배치 복구. 검증 실패는 필드·행·원인만 표시하고 게시 불가. 중복 요청·동시 게시 충돌은 중복 반영 없이 재확인을 요구한다.

## 6. 관리자·보안·운영

MVP 관리자는 가상 fixture 게시·복구에 한정한다. 실제 데이터 전환, 권리 승인 자체의 자동화, 사용자 관리, 원천 수치의 화면 직접 편집은 제외한다. 공개 기능에는 관리자 계정이 필요하지 않다.

모든 관리자 조회·미리보기·게시·복구는 서버에서 인증·역할을 검사한다. UI 숨김만으로 보호하지 않는다. 기본 거부, 세션 만료 시 재인증, 쓰기 요청 위조 방어, 입력 파일 크기/행 수 제한, 공개 허용 필드 검증을 적용한다. 관리자 인증 방식과 파일 제한 수치는 P1/P2 ADR에서 확정하고 배포 전 검증한다. 인증이 준비되지 않으면 관리자 경로·API를 닫으며 MVP 수락은 보류한다. 가짜 로그인이나 클라이언트 비밀번호로 대체하지 않는다.

게시 단위는 검증 완료 배치 전체이며 실패 시 기존 배치를 보존한다. 감사 이력에는 관리자 내부 ID, 동작, 대상 배치, 시각, 성공/실패만 기록하고 비밀번호·세션·원본 개인정보는 남기지 않는다. 초기에는 단일 앱·로컬 fixture를 우선하며 별도 서비스·유료 인프라는 도입하지 않는다. 영속 저장·인증 기술은 P1에서 실행 환경과 함께 결정한다.

## 7. 우선순위와 릴리스

우선순위 Must는 해당 릴리스 완료 조건, Should는 후속 후보, Could는 재검토 대상이다. 난이도 S=국소 화면/문서, M=여러 화면·계약, L=모델·보안·통합 검증으로 공수 확정값이 아니다.

| 릴리스 | 기능 | 우선순위 | 난이도 | 선행 조건 |
| --- | --- | --- | --- | --- |
| MVP (P1~P5) | strict 앱 기반·기본 상태·독립 Git 경계 | Must | M | P0 수락 |
| MVP | 버전 계약·공개 필드 검증·가상 fixture·추적성 | Must | L | P1 |
| MVP | 역할별 모델·부족 표본·휴식 처리 | Must | L | P2, P3 ADR |
| MVP | 홈·검색·상세·랭킹·두 선수 비교·소개 | Must | L | P3 |
| MVP | 등록/출전 구분·시즌/대회/팀 필터·URL 복원 | Must | M | 등록 fixture 포함 P2 |
| MVP | 별도 권한 관리자·배치 미리보기/게시/복구 | Must | L | 인증·저장 ADR 및 서버 거부 검증 |
| MVP | 접근성·모바일·성능·보안·운영 검수 | Must | M | P4 |
| V1.1 | 브라우저 로컬 즐겨찾기, CSV 내보내기, 추가 구간 선택 | Should | M | 개인정보/재배포 권리 검토, 모델 비교 가능성 검증 |
| V1.1 | 승인 공급자 파일 어댑터·실제 데이터 모드 | Should | L | 권한 증빙·표시 의무·저장/공개 범위, 별도 ADR·검수 |
| V2 | 승인된 자동 갱신·실패 알림·운영 규모 확대 | Could | L | 공급 계약·수집 권한·운영 예산 확정 |
| V2 | 계정 기반 동기화·추가 분석 | Could | L | 수요 검증·개인정보 검토·별도 PRD |

실제 데이터 승인이 없어도 MVP는 데모로 완결한다. P0에서 앱 구현·설치를 진행하지 않는다. 기능 제외가 필요하면 PRD/ADR/수락 기준을 명시적으로 변경하고 승인된 범위를 기록한다.

## 9. 개인정보·법적 표시·디자인 권리

다음은 제품 출시 확인 항목이며 특정 법률의 적용 여부를 확정하는 법률 의견이 아니다. 외부 서비스 연동과 실제 공개 전에 운영 주체·서비스 형태·처리 데이터에 맞는 검토를 수행한다.

- 일반 이용자는 이름·이메일·생년월일·위치·연락처를 제출하지 않는다. 검색어를 분석 로그에 원문 저장하지 않는다. 관리자 계정은 운영에 필요한 최소 식별자와 인증 정보만 처리한다.
- IP·접속 로그·오류 로그·관리자 감사 이력도 개인정보 포함 가능성을 검토한다. 항목·목적·접근자·보관 기간·파기·처리위탁/국외 이전 여부를 P5 전에 문서화한다. 불필요한 추적 쿠키·제3자 분석 SDK는 도입하지 않는다.
- 소개/푸터에 운영 주체, 문의 경로, DEMO/비공식·비예측 안내, 데이터 출처·기준일, 저작권·상표 안내, 서비스 이용 조건을 제공한다. 개인정보 처리방침·쿠키 안내/동의 등 필요한 표시 여부는 실제 처리 항목과 적용 요건에 따라 검토하고 누락을 해소한다. 미정 연락처나 허위 사업자 정보를 게시하지 않는다.
- 자산 목록에 파일/사용 위치/제작자/출처/라이선스/상업 이용·수정·재배포 범위/표시 의무/확인일을 기록한다. 폰트·아이콘·차트 라이브러리도 포함한다. 권리 미확인 로고·선수 사진·리그 마크·브랜드 유사 자산은 넣지 않고 자체 텍스트·도형을 사용한다.
- 실제 데이터 도입 전 수집·저장·가공·공개·재배포·보관·종료 시 삭제 범위와 계약 유효기간을 확인한다. 공개 웹에서 볼 수 있다는 이유만으로 재사용 권한을 가정하지 않는다. 비밀 증빙 원문은 저장소나 공개 응답에 넣지 않는다.

## 10. 미결정 사항과 구현 진입 조건

현재 앱·패키지·스키마·점수 계산기는 없다. 본 문서는 산출물이자 검수 계약이며 구현 증거가 아니다.

| 결정 | 담당 단계 | 결정 전 안전 동작 |
| --- | --- | --- |
| 프레임워크·런타임·독립 저장소·관리자 인증/저장 | P1, ADR-003/005 | 설치·인증 완료를 주장하지 않음, 관리자 기본 거부 |
| 버전 입력 스키마·입력 크기/행 제한·등록 이력 모델 | P2 | 고정 가상 fixture 설계만, 미검증 게시 금지 |
| 기세 산식·윈도·최소 표본·가중치 | P3, ADR-002 | 모델 미확정, 점수/순위 생성 금지 |
| 운영 주체·문의·로그 보관·자산 권리·법적 표시 | P5 | 공개 출시 보류, 개인정보·무권한 자산 추가 금지 |
| 실제 데이터 공급·갱신 주기 | 별도 승인, ADR-001 | DEMO 전용, 외부 연동 없음 |

P1 준비는 이 PRD와 ADR의 범위 확인부터 시작한다. 다음 단계 완료는 각 로드맵 수락 기준과 실제 실행 결과로만 판단한다.


### R05 채택 규칙 (ADR-030, 기존 상충 설명 대체)

원값(저장된 score/deltaScore의 정확한 수치)으로 정렬·동점을 판정한다. score는 내림차순(0 포함), change는 deltaScore > 0만 내림차순, decline은 deltaScore < 0만 오름차순이다. 0 변화와 null 변화는 변화 탭에서 제외한다. 동점은 공동 순위 1,1,3, playerId ASCII 오름차순이며 전체 필터 결과에서 순위를 부여한 뒤 페이지를 나눈다. 표시는 최종 UI에서만 소수 첫째 자리로 반올림하므로 표시값이 같아도 순위는 다를 수 있다. score=null·등록 미확인·표본 미달·중간 미만 신뢰도는 모든 순위에서 제외한다.
API는 동일 조건의 보드와 같은 원값·순위를 반환한다. `sort=score|change|decline`, 선택 `date`(KST)·`team`, 기존 role/window/season/competition/page/limit을 사용한다. API의 기본 기간은 역할별 권장값이므로 URL과 비교할 때 window를 명시한다.

R04 명확화 (2026-11-03): 선수 탐색의 팀 선택은 해당 팀 출전 로그를 제한한 후 최근 N 역할 출전을 집계한다. 기세 랭킹의 팀 선택은 전체 최근 표본 내 해당 팀 소속 이력 선수 필터이며, 점수와 핵심 지표는 전체 표본이다. 팀별 기세 모델은 미정이며 제공하지 않는다. 최근 N은 팀별로 독립적이므로 팀별 N의 합과 전체 N은 다를 수 있다.

### R06/R07/R09 채택 규칙 (ADR-032, 기존 상충 설명 대체)

기세 변화량은 같은 선수·시즌·대회·역할·N·모델 버전의 이전 순위 적격 게시 점수 대비다. 자료가 없으면 비교 불가다. 모델 내부 이동 창 점수차(최신 출전 하나를 제외한 N출전 대비)는 별도 용어로 설명하며 비중첩 이전 창과 혼용하지 않는다. API/read/UI는 비교 양쪽의 시즌·대회·역할·N·모델 버전·스냅샷·asOf와 provenance를 전달한다.
비교 3슬롯 이상은 명시적 오류와 2개 이하로 수정하는 안내를 제공한다. 선수 탐색은 시즌 출전 목록이며 등록 스냅샷 없는 선수는 등록 여부 미확인이다. 현재 1군 등록을 출전 로그로 재구성하지 않는다. 현재 DEMO는 2026 정규시즌만 지원하며 관련 화면에 표시한다.
