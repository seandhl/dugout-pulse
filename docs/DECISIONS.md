상태: 제안 / 채택 / 폐기 / 대체. 변경 시 기존 기록을 지우지 않고 새 ADR로 대체 관계를 연결한다. 날짜 기준은 Asia/Seoul이다.

## ADR-001: 승인 전 데모 전용

- 날짜: 2026-11-03
- 상태: 채택
- 구분: 데이터 권한·제품
- 배경: 데이터 공급 계약, 계정 권한, 이미지·로고 사용 허가를 확인하지 못했다.
- 결정: 데이터 공급 계약/승인 없음 → 데모 모드만 허용. P0 외부 수집 금지. 이후도 승인된 형식의 가상 fixture를 기본으로 사용한다.
- 대안: 승인되지 않은 수집·실제 선수 기록 추정은 채택하지 않는다.
- 영향: DEMO 표시와 출처·as-of·시즌·대회·표본 추적은 데이터 계약부터 UI까지 유지해야 한다. 실서비스 데이터 연동은 별도 권한 검토가 필요하다.
- 검증/재검토 조건: 공급자, 사용 목적, 수집·저장·재배포 범위, 유효기간, 표시 의무를 증빙으로 확인하고 새 ADR로 활성화 여부 결정.

## ADR-005: 공개 열람과 별도 권한 관리자

- 날짜: 2026-11-03
- 상태: 채택 (제품 범위); 인증·저장 기술은 P1 제안/검증 대상

## ADR-008: 단일 앱과 PostgreSQL 컨테이너 아키텍처

- 날짜: 2026-11-03
- 상태: 채택 (구조·기술 선택); 설치·호환성·보안·실행 검증 미완료
- 구분: 기술·데이터 경계
- 배경: PRD의 원자 게시·복구·감사·서버 권한 요구와 사용자가 지정한 기본 스택을 단일 저장소에서 충족해야 한다.
- 결정: [ARCHITECTURE](ARCHITECTURE.md)의 Next.js App Router + TypeScript strict 단일 pnpm 앱, PostgreSQL + Prisma, Zod, Tailwind/Radix 기반 소유 UI, Recharts, Vitest/Playwright를 채택한다. 기본 배포는 Node 컨테이너다. 순수 stats/momentum, 읽기 서비스, 수입/게시, repository와 task 경계를 분리한다. 마이크로서비스는 도입하지 않는다.
- 대체 관계: ADR-003의 기술 제안을 구조 선택에 한해 대체한다. 설치 검증 조건은 유지한다. ROADMAP의 “초기 별도 DB 미도입”은 P0 미실행 및 fixture 입력 우선으로 한정하고, P2 이후 게시·복구 영속성은 PostgreSQL로 결정한다. ADR-005의 관리자 인증 방식은 P1 검증 전까지 제안 상태다.
- 대안·근거: SPA+별도 API는 경계 중복, 파일만의 게시 저장은 원자성·감사 제약이 있어 제외. Vercel은 향후 배포 adapter 대안으로 유지한다.
- 버전 근거: 공식 npm metadata 조회 성공; Prisma latest=8.0.0-rc.29는 제외하고 안정 7.10.1 선택. 전체 버전·출처·미검증 사항은 ARCHITECTURE에 기록한다.
- 영향·위험: 불변 배치·release 포인터·권리 재검사·idempotency와 실제 PostgreSQL 통합 검증 필요. 모델 산식은 P3 결정 전까지 미확정이다.
- 마이그레이션: 현재 DB·코드 없음. P2 최초 스키마 및 이후 버전 변환·migration·회귀 테스트 필요.
- 검증: P0 문서 정합성만 검사. P1 설치·strict/lint/build, P2 DB 계약, P4 동시 게시·권한·E2E, P5 복구·성능 검증을 남긴다.
- 재검토 조건: peer/런타임 충돌·지원 종료·보안 공지·실측 성능/작업 시간 초과 시 새 ADR. 현재 외부 연결·패키지 설치·배포 승인 없음.


## ADR-009: v1 데이터·조회·화면 계약

- 날짜: 2026-11-03
- 상태: 채택 (설계 계약); 스키마·API·UI 실행 검증 미완료
- 구분: 데이터·제품·보안
- 배경: 구현 전에 ID·숫자·기간·권한·상태 해석을 고정해야 한다.
- 결정: [DATA_DICTIONARY](DATA_DICTIONARY.md), [API_CONTRACT](API_CONTRACT.md), [SCREEN_SPECS](SCREEN_SPECS.md)를 v1 구현 계약으로 채택한다. playerId는 이름/등번호/팀과 독립, 투구는 아웃 정수, BB는 IBB 포함, 미제공은 null이다. 최근 구간은 확정된 선수 출전/평가 role 등판 기준이며 cutoff 이하 completed_at 순서다. 같은 시각은 gameId ASCII 오름차순이다. 중단은 제외하고 재개 final을 같은 경기 한 표본으로 센다. 정정은 새 완전 배치/release로 게시한다.
- 세부 기본값: 공개 목록 20명/최대20, 이름 Unicode 정렬+ID 안정 순서, 통계 recent N=타자10/선발5/불펜10(최대100), 검색100자, 비교 정확히2명, 입력5MiB/50,000행을 계약 한도로 채택한다. 성능 실적을 의미하지 않는다. role별 모델 윈도·최소 표본·산식·0~100 범위는 ADR-002의 P3 결정으로 남긴다. 모델 미확정 시 점수/변화/순위는 생성하지 않는다.
- 기간 결정: 휴식·사용량·기간 표시는 경기 완료일 KST 기준이다. 과거 cutoff는 해당 release의 사후 정정이 포함된 재구성이고 당시 공개값 재현은 당시 releaseId로 한다. 장기 미출전 이유는 추정하지 않는다.
- 권한/캐시: 서버가 DEMO/APPROVED 모드를 고정하며 현재 DEMO만 허용한다. 공개 GET은 비로그인 읽기 전용, 관리자 서버 기본 거부 유지. 매 요청 현재 권리 검사, v1 no-store·영속 수치 캐시 없음. APPROVED의 offline 권리 재검증 불가 시 메모리 수치도 숨긴다.
- 대체 관계: ADR-006의 페이지 크기와 통계 조회 윈도 제안을 계약으로 구체화한다. 모델 결정은 대체하지 않는다. A-015의 입력·검색 한도만 채택하며 JS/차트 성능 예산은 미검증 상태 유지. ADR-008의 release·배치·서버 경계를 유지한다. ARCHITECTURE의 추가 조회 경로 teams/games/appearances/rosters/sources는 확장 후보이며 이번 8종 endpoint의 필수 구현 완료를 대체하지 않는다.
- 영향: 화면·API·계산은 동일 scope/release를 유지해야 한다. 최근 N은 팀별 합과 전체 합을 합성하지 않으며, 시즌 합계만 팀별 합과 일치한다. 원천 결측은 지표별 전체 합계 null, 알려진 부분합은 별도 표시한다.
- 마이그레이션: 기존 코드/DB 없음. 이번은 문서 추가라 실행 migration 없음. P2 최초 스키마·Zod·DB 제약·fixture로 구현하고, 이후 파괴적 변경은 major/변환/migration/회귀 검증 필수다.
- 검증/재검토: JSON 문법·내부 링크·필수 항목 문서 검사만 수행한다. P1 실행 기반, P2 계약/DB, P3 모델 ADR, P4 HTTP·권한·상태/접근성 E2E 검증 전 단계 완료·출시를 주장하지 않는다. 공급자 필드/타임스탬프 미지원이면 값을 추정하지 않고 어댑터 계약을 재검토한다.

### ADR-009 문서 검증 기록

- 2026-11-03, 프로젝트 루트에서 외부 네트워크/패키지 없이 `python3 - <<'PY' ... PY` 표준 라이브러리 검사 실행, exit 0.
- 검사: 세 신규 문서의 코드 fence/로컬 링크, 12 엔티티 제목·필수 타격/투구 필드·8 API 경로·7 화면/상태 존재, JSON 블록 9개 `json.loads`, 목록/상세 예시 동일성, TB 수식 및 OPS 예시 오차 <1e-12, 모델 미확정 null, README/docs 전체 로컬 링크.
- 결과: 문서 구조·예시 정합성 PASS. 의미 전부의 기계적 증명/앱 API·DB·모델·화면 접근성 테스트는 아님. 실행 앱/스키마 부재로 해당 검사는 미실행. 수동으로 기간/GS/role·release/cursor·권리·결측 계약을 대조했다.

## ADR-실행-API-01: 읽기 경계의 단계 도입 (2026-11-03, 채택)

공개 페이지를 `(public)` 그룹으로 이동하고 contracts → 읽기 서비스/ports → fixture repository를 도입한다. HTTP는 입력/응답 검증과 오류 매핑만 맡는다. 모든 server 모듈은 server-only로 보호한다. DEMO fixture의 마지막 갱신은 fixture 제작 시각으로 해석한다. 기존 상세 API 설계의 확장 필드는 이후 단계로 남기며 현재 미지원 입력은 거부한다.

DB 접속용 Prisma 패키지가 설치되지 않았으므로 이번 설치 금지 조건 아래 실제 Prisma 인스턴스를 만들지 않는다. `db/client.ts`는 생성 클라이언트 factory를 받는 프로세스 singleton과 명시 종료 함수를 제공한다. `repositories/database.ts`는 공개 projector의 DTO 검증 경계만 제공하며 Prisma 쿼리 구현이 아니다. 실제 DB repository, 권리/게시 트랜잭션, 프로세스 종료 hook 연결 및 DB 통합 검증은 후속 작업으로 남는다. DB 구현을 완료한 것으로 보고하지 않는다.

## ADR-INGEST-01: 공급자 계약과 별도 공개 gate (2026-11-03, 채택)

DataProvider의 DEMO/LICENSED_FILE/LICENSED_API를 기존 공개 DataMode와 분리한다.
서버 registry의 출처·라이선스를 수입과 공개에서 각각 검사하며 파일의 자체 권리 주장은
신뢰하지 않는다. API transport와 자격증명 계약이 없으므로 LICENSED_API는 항상

기존 DB와 공개 API 계약을 변경하지 않는 서버 계약 추가이므로 DB migration은 없다.
공식 공급자 연결 절차와 필드 매핑은 PROVIDER_GUIDE.md에 기록한다.

## ADR-INGEST-02: 샘플 업로드 전용 비공개 staging

- 날짜: 2026-11-03
- 상태: 채택 (샘플 ingest 범위)
- 결정: 서버에 명시적으로 설정한 SHA-256 관리자 capability 검증을 사용하고 미설정은 기본 거부한다.
  현재 권한은 자체 샘플 checksum allowlist에만 한정한다. 업로드한 라이선스/역할은 신뢰하지 않는다.
  Zod 행 검증 및 외부 ID 매핑 후 비공개 `.demo/ingest`에 append-only 결과를 저장한다.
  공개 repository와 연결하지 않으며 오류 배치는 전체 REJECTED, 모든 게시 동작은 비활성이다.
- 마이그레이션: 기존 DB/API 계약 변경 없음. 로컬 staging은 DB import schema와 별도인 샘플 adapter다.

## ADR-INGEST-03: 관리자 승인 DEMO publish (채택, 2026-11-03)

ADR-INGEST-02의 게시 비활성 결정을 DEMO 샘플에 한해 대체한다. 기존 정규 공개 fixture/API는 유지하며,
업로드 승인 결과는 `/published`, `/api/v1/published`로 제공한다. 임의 외부 업로드는 여전히 차단한다.
자체 제작 정정 샘플을 allowlist에 추가한다. 외부 계약 승인이나 운영 DB 구현을 의미하지 않는다.

저장소는 `.demo/pipeline/state.json` v1이며 raw(base64), 최초/후속 검증, 행 버전 이력, 관리자 승인 감사,
현재 공개 행, 파생 합계와 재계산 이벤트를 함께 보관한다. 디렉터리 lock으로 writer를 배타 처리하고
임시 파일 fsync 후 atomic rename을 commit으로 사용한다. commit 이전 실패는 기존 공개본을 유지한다.
다른 writer는 409를 반환한다. 프로세스 비정상 종료 후 lock이 남으면 운영자가 프로세스 종료를 확인하고
lock 디렉터리만 제거한다. 자동 만료로 실행 중인 writer의 lock을 탈취하지 않는다.

같은 논리 키의 upsert로 공개 행 중복을 방지하며 업로드/승인 시도 감사는 별도로 누적한다.
정정은 공개 데이터를 기준으로 재검증하고 이전 as-of보다 오래된 변경은 거부한다.
하나의 오류라도 전체 배치를 중단한다. 기존 출전 기록을 깨뜨리는 로스터 정정도 중단한다.
출전은 같은 시즌/대회·공식 경기 날짜의 REGISTERED 로스터·경기 팀이 확인될 때만 게시한다.
취소/연기/중단 등 FINAL 이외 경기는 출전 로그를 제거하며 원본과 이전 버전은 보존한다.
재개 경기는 같은 game_id를 유지하고 FINAL 및 official_final=true일 때만 출전을 게시한다.

기존 Prisma schema 및 DB 계약은 바꾸지 않는다. 로컬 v1의 audit/validations 추가 필드는 읽기 시
빈 감사 목록/기존 검증본으로 보완한다. 그 외 버전은 거부한다. 운영 DB로의 이관은 별도 제안 상태다.

## ADR-SCOPE-01: 날짜별 1군 범위·freshness (채택, 2026-11-03)

수동 DEMO import 저장소를 그대로 사용한다. `snapshot_on`이 로스터 asOfDate이며
`effective_on`은 소속 효력일, `as_of`는 정정 기준시각이다. 선수/코치를 person_type으로 분리하고
COACH 역할의 경기 로그는 거부한다. 기존 v1 person_type 누락은 PLAYER로 읽는 추가적 마이그레이션이다.
`valid_until` 누락 시 해당 스냅샷 날짜만 유효하다. 조회일 이전 최신 스냅샷이 UNKNOWN 또는 만료면
과거 등록으로 대체하지 않고 ‘엔트리 정보 없음’을 표시한다. 과거 출전 검색은 이 필터와 독립적이다.
전체 팀의 명단 완전성을 추정하지 않으며 입력된 스냅샷 범위만 제공한다.

`/api/v1/scope`와 `/published`는 season, competition(regular 기본/postseason/allstar/exhibition),
date(KST), search(appeared/registered), q를 받는다. 날짜는 경기 귀속일과 스냅샷 날짜를 각각 조회한다.
시즌 숫자 입력은 확장 가능하며 실제 제공 시즌을 별도로 안내한다. 현재 게시 권리는 2026 자체 DEMO만 허용한다.
시즌 중 여부를 추론하지 않는다. 마지막 출전일·출전 표본·실제 데이터 기준시각을 표시한다.
과거 날짜 조회는 경기 귀속일·스냅샷 날짜를 기준으로 현재 보유한 최신 정정본을 사용한다.
정정 시각(as_of)은 조회일 이후일 수 있으며 숨기지 않고 표시한다.
당시 알려진 원본 전체를 재구축하는 시점 복원 API는 제안 상태이며 history 원본은 보존한다.

freshness 정책은 48시간(운영 SLA가 아닌 DEMO 기본값), 알림은 미연결 placeholder다.
스케줄러는 비활성이고 라이선스 API 계약·연결 후에만 도입한다(제안).
검증 및 게시 시도마다 runs를 원자적으로 누적하고 실패 사유·최근 시도·최근 게시 성공을 제공한다.
기존 저장소의 runs 누락은 기존 batches에서 이력을 읽는다. 성공은 게시 완료를 뜻하며 검증 성공과 구분한다.
인증/파일 파싱 이전 거절과 파일 저장 자체 실패는 pipeline run에 포함되지 않으며 HTTP 오류로 보고한다.
DB schema는 변경하지 않으며 운영 DB 이관은 후속 제안이다.


## ADR-014: 설명 가능한 기세 v0.1 계산 사양

- 날짜: 2026-11-03
- 상태: 채택 (계산 사양에 한정, 구현·공개 활성화 전)
- 관계: ADR-002의 역할 분리 원칙을 유지하고 미결정 계산 항목을 구체화한다.
- 결정: [MOMENTUM_MODEL](MOMENTUM_MODEL.md)의 역할별 feature, 출전 N=10/5/10, robust median/MAD 정규화, 수준/시즌 변화/직전 변화 55/30/15, 표본 수축, 고정 임계값과 결측·휴지·설명 정책을 v0.1 사양으로 채택한다. 상수는 DEMO 개발 기본값이며 실증 최적값이 아니다.
- 영향: 기존 API·DB·UI는 변경하지 않고 model_pending을 유지한다. 공식 기록·확률 표현과 역할 간 비교를 금지한다. 실제 활성화에는 계약 갱신, 필요한 migration, raw/cohort fixture 및 경계·회귀·화면 검증이 필요하다.
- 제안/미채택: 실제 데이터 보정값, 다른 시즌/대회 baseline 대체, ERA 가중, 역할 통합 점수는 채택하지 않는다.
- 검증/재검토: 문서 예시 수식 검산과 형식 검증을 수행한다. 모델 구현과 P3 수락 테스트는 별도 단계다. 설정 변경 시 새 버전과 release를 사용한다.

## ADR-015: 기세 순수 계산 라이브러리 (채택, 2026-11-03)

- `src/stats/momentum.ts`에 ADR-014의 역할별 고정 v0.1 설정과 계산을 구현한다. 외부 의존성·현재 시각·난수·외부 수집을 사용하지 않는다. 권한 있는 자체 DEMO 입력만 허용한다.
- `scoreMomentum`은 원점수와 N/A status/eligibility를 반환한다. 반올림은 호출하는 presentation layer의 책임이며 계산·정렬에는 넣지 않는다. 사용자 임의 설정 변경은 제공하지 않고 `momentumConfig`로 고정 설정 복사본을 노출한다.
- W/S는 분리한다. V는 최신 출전 하나를 제거한 N개 이동창이라는 명세를 유지한다. V의 S 중첩은 설명에 남기며 현재/직전 재계산에 같은 S·cohort·feature 집합을 쓴다.
- baseline 추출은 선수당 한 관측값, 동일 scope/release, W 시작 경계 이전, 평가 선수 제외 정책이다. source/inputRef/asOf/revision과 raw 행을 설명 artifact에 유지한다.
- `fnv1a32` 식별자는 재현 확인용이며 암호학적 무결성 증명이 아니다. 게시 계층의 권한·원본 해시·release 승인/저장 계약을 대체하지 않는다.
- API/DB/UI 및 `model_pending`은 유지한다. 이번 채택은 내부 계산과 DEMO 단위 검증이며 실제 데이터 보정·공개 활성화 승인이 아니다.

## ADR-017: DEMO 스냅샷 게시와 역할별 API (채택, 2026-11-03)

- 공개 DEMO 버전은 `momentum_v0_1_0_windows_v1`이다. 기존 v0.1 골든 결과는 보존하며 3/5/10/20 역할별 실제 출전 창을 지원한다. 기본값은 타자·불펜 10출전, 선발 5선발이다. 최소 PA/BF/아웃과 cohort 게이트는 기존 역할별 정책을 유지한다.
- 현재 실행 저장소는 `.demo/pipeline/state.json`이다. 파일 잠금·fsync·원자적 rename으로 원본, 집계, 스냅샷, 현재 포인터를 함께 게시한다. PostgreSQL/Prisma 실행 연동을 구현했다고 간주하지 않는다.
- SHA-256(정렬된 입력+공개 모델 버전)을 스냅샷 ID로 사용한다. computedAt은 첫 생성 때 고정한다. 재실행은 기존 ID를 재사용한다. 정정은 입력 provenance/revision이 달라 새 ID를 생성하며 이전 객체는 삭제하지 않는다. 동시 게시 충돌은 409로 재시도한다.
- deltaScore는 같은 선수·역할·창·시즌·대회·algorithmVersion의 이전 **순위 적격** 스냅샷 중 게시 revision이 가장 큰 결과와 비교한다. 이전 대상이 없으면 null이다. 순수 모델 내부 V 비교(delta)와 API deltaScore는 다르며 둘을 혼용하지 않는다.
- 높은/중간 신뢰도 + 등록 로스터 + 산출 점수만 본 순위에 포함한다. 낮은 신뢰도, 미산출, 비등록/미상/유효기간 만료 로스터는 excluded로 반환한다. change 정렬에서 이전 유효 결과가 없으면 excluded에 남기고 deltaScore=null로 표시한다. 동점은 playerId 순이며 정렬은 반올림 전 점수로 수행한다.
- 같은 날짜도 gameId와 doubleheader_no로 구분한다. 정정·취소는 기존 ingest 검증과 이력을 거쳐 전체 cohort 의존 점수도 같은 게시에서 갱신한다.
- 입력 확장은 선택 필드 추가다. 과거 파일은 그대로 유효하고 누락 값은 0으로 채우지 않는다. 투수 BB 정의 미제공 시 BB를 결측으로 처리한다. 실제 데이터/외부 수집은 여전히 금지하며 모든 응답은 DEMO다.

## ADR-018: 오프라인 DEMO 평가와 실데이터 실행 차단 (채택, 2026-11-03)

- 운영 산식은 변경하지 않고 별도 평가 CLI/파라미터 experimentId와 reports 산출물을 둔다. core scoringVersion 혼합은 실패한다.
- 실제 실행은 권리 증거·coverage·100경기 screening floor를 요구한다. 100은 통계적 충분성의 증명이 아니다. 현재 licensed point-in-time adapter가 없어 모든 실제 실행은 차단한다.
- 실제 backtest runner, 미래 성적 비교 설계·실행, 리그별 파라미터 채택은 제안/미구현 상태다. 합성 점검으로 예측력을 주장하지 않는다.

## 홈 fixture 분석 (채택 · 2026-11-03)

- 홈은 `/api/v1/home?role=batter|starter|reliever&window=3|5|10|20`에서 모든 기록 수치를 받는다. 기존 API 계약은 변경하지 않는다.
- canonical SQLite DEMO fixture의 정정 반영 완료 경기만 기존 momentum v0.1 계산기에 전달한다. 생성기가 지원하지 않는 사구·희생타·고의사구 등 사건은 이 시뮬레이션 규칙에서 0이며, 실제 기록의 결측값 보정 규칙으로 사용하지 않는다.
- TOP5는 최근 기세 점수 내림차순이며 이전 게시 대비 상승폭 순위가 아니다. 낮은 신뢰도와 미산출은 제외하고 별도 안내한다. 동일 점수는 선수 ID순.
- 분석 카드 선정은 선택 역할·기간의 계산 가능한 표본 경기 수 내림차순, 동점은 ID순이다.
- fixture는 현재 1군 등록을 보증하지 않는다. 등록 미확인을 표시하며, 홈 목록은 공식 게시 랭킹과 분리된 DEMO 분석이다.

## 선수 탐색 (채택 · 2026-11-03)

- 기존 커서 API 계약을 보존하고 `/api/v1/player-directory`에 검증된 검색 조건과 서버 측 20명 페이지네이션을 추가한다. URL은 이름, 팀, 시즌, 역할, 선수 범위, 기간, 정렬, 페이지를 재현한다. 동점은 이름/선수 ID로 고정한다. 제공되지 않는 조건은 400이다.
- 팀은 완료 경기 출장 소속을 기준으로 하며 이적 선수는 양쪽 팀에 포함한다. ID는 이름/등번호와 독립적이다. 현재 1군·주 포지션·등번호·점수 변화는 원천 미제공으로 명시하며 임의 생성하지 않는다.
- OPS 필수 카운트가 없는 원천에서는 null이다. ERA는 기록 아웃 수가 있을 때만 계산한다. 결측 지표는 정렬에서 마지막에 배치한다. 기세는 기존 역할별 모델을 재사용한다.
- fixture 릴리스/업데이트/기간별 기세 계산을 최대 4건 메모리 캐시한다. DB 스키마 변경과 외부 수집은 없다.

## 타자 상세 (채택 · 2026-11-03)

- `/api/v1/players/[id]/batting?window=3|5|10|20|season`은 canonical DEMO의 확정 경기 원시 기록을 합산한다. 기존 선수 API는 보존한다. 시즌/대회는 fixture의 2026 정규시즌으로 명시한다.
- OBP/OPS 결측 정책은 선수 탐색과 동일하다. 기세는 결측 feature를 기존 모델의 제외 규칙으로 처리하고, 산출되는 경우 실제 기여 설명을 표시한다. 시즌 전체 기세는 제공하지 않는다.
- 차트는 선택 기간 누적 비율과 최대 5출전 원시 합산 비율이다. 한 번에 한 지표만 표시하며 결측 구간은 연결하지 않는다. 원천 참조와 정확한 표시 비율을 표로 제공한다.
- compare 추가는 URL로 선택한 타자를 전달한다. 최대 두 타자 요약을 지원하며 영구 저장하지 않는다. DB 변경·패키지 설치·외부 수집 없음.


## ADR-021 · 채택 · 투수 상세와 역할별 통계

- 타자 상세의 작업 메뉴·프로필·DEMO·원천 추적 footer를 공통 컴포넌트로 추출한다. 통계 계산/read/API는 타자와 독립시킨다.
- 투수 URL은 `role=starter|reliever`, 선발 3/5/10, 불펜 5/10/20 및 역할 시즌을 지원한다. 호환되지 않는 기간은 400으로 거부한다. 최초 역할은 서버의 선수 등록 역할에서 결정한다.
- 시즌 전체는 모든 투구 역할, 역할 시즌은 해당 역할만, 최근은 해당 역할 등판만 합산한다. 등판의 역할은 line에 명시하며 선수의 등록 역할로 추정하지 않는다.
- IP는 정수 outs가 원본이다. 5.2는 17 outs이며 비율은 합계 outs/3을 분모로 계산한다. 표시값을 실수로 재해석하거나 경기별 비율을 평균하지 않는다.
- optional pitches는 모든 선택 등판에 제공됐을 때만 합계를 표시한다. 미제공 구종·구속 차트는 생성하지 않는다. HLD/SV는 기회 의존 기록으로 설명하고 기세 점수에 포함하지 않는다.
- 기존 선발/불펜 모델과 baseline 계약을 유지하며 실제 중앙값·기준 선수 수·표본 수축·지표 기여를 공개한다. 점수 보류 상태에서도 baseline 조건 미달을 표시한다.
- 합성 fixture payload 확장에 DB 스키마 변경은 없다. 기존 DEMO payload는 seed로 원자적으로 교체하고 이벤트/시즌 합계 및 새 canonical digest를 검증한다.

## ADR-022 · 채택 · 게시 스냅샷 랭킹 (2026-11-03)

- `/rankings`는 수동 게시 pipeline의 immutable momentumSnapshots만 읽는다. 홈/탐색의 요청 시 fixture 계산을 랭킹으로 사용하지 않는다. 기준일은 KST asOf 날짜이며 미지정 시 해당 시즌·대회·기간의 최신 게시일이다.
- 최신 날짜는 momentumCurrent manifest를 사용한다. 과거 날짜는 가장 높은 publicationRevision의 보존 스냅샷만 사용한다. 과거 전체 manifest는 저장되지 않으므로 당시 전체 선수 목록 복원은 보증하지 않는다. 과거 manifest 영속화는 제안 상태다.
- scoringVersion은 algorithmVersion/modelVersion 모두 현재 채택 버전과 일치해야 한다. 한 게시 묶음에 다른 버전이 있으면 전체를 기록 미갱신으로 처리한다. 버전 fallback은 없다.
- 표본 summary.W와 sampleSize를 모두 검사한다. 등록·eligible·ranked·중간 이상 신뢰도와 역할별 중간 표본 기준을 만족한 선수만 포함한다. 제외 수를 역할별로 표시한다.
- 저장 점수를 소수 첫째 자리로 투영한 동일 값으로 서버 정렬 후 20명 페이지를 만든다. 동점은 playerId ASCII순이다. 상승/하락은 저장 deltaScore의 양/음수만 포함하며 비교 없음은 생성하지 않는다. 팀은 해당 snapshot inputRefs로 복원한 최근 표본의 출장 소속이다.
- 기존 `/api/v1/rankings` 계약은 유지한다. 새 페이지의 서버 read는 별도이며 기존 API의 raw 정렬과 동일 계약이라고 주장하지 않는다. 현재 게시 저장소는 JSON 파일 기반 DEMO다. 운영 DB ORDER BY 및 SQL/표시 일치 통합 검증은 DB adapter 연결 후 필요하다. 스키마 변경·패키지 설치·외부 수집 없음.

## ADR-023 · 채택 · DEMO 선수 비교 (2026-11-03)

- `/compare`는 기존 canonical DEMO fixture와 역할별 상세 read를 재사용한다. 새 데이터 수집·패키지·스키마 변경은 없다.
- `players`의 쉼표 구분 두 슬롯, `role1/role2`, `window`, `season`, `competition`, `q`를 URL에 보존한다. 빈 첫 슬롯도 유지하며 서버 GET 폼·링크로 새로고침/뒤로가기/키보드 복원을 지원한다.
- 공통 기간은 모든 모델이 지원하는 최근 5/10출전 및 시즌 전체다. 달력 기간이 아닌 역할별 출전 수이며 실제 날짜는 다를 수 있다. 시즌 기세는 기존 계약대로 미제공이다.
- 같은 역할의 서로 다른 선수만 공통 막대를 표시한다. 다른 역할은 점수/능력 우열 비교 불가를 명시하고 기록을 분리한다. 동일 선수·결측 지표·요청 출전 수 미달은 막대 비교에서 제외한다. 기술통계와 모델 신뢰도는 별개다.
- 막대는 지표별 두 값의 최대 절댓값을 공통 분모로 사용한다. 음수의 부호는 숫자로 보존하고 이미지 설명에 절댓값임을 명시한다. 낮을수록 좋은 지표를 표시하며 IP는 우열이 아닌 투구량이다. IP 계산은 outs/3, 표시는 야구식 .1/.2다.
- 시점 불일치 경고를 제공하나 현재 canonical 단일 release에서는 모든 as-of가 같다. 외부/선수별 시점 adapter는 미연동이다. 미지원 시즌·대회에는 기존 시즌 기록을 대체 표시하지 않는다.

## ADR-024 · 채택 · 상세 차트와 경기 로그 분석 (2026-11-03)

- 타자·선발·불펜 상세는 같은 games 항목의 raw counts 및 서버 통계 엔진 결과(stats/cumulative/moving)를 공유한다. 클라이언트는 좌표 변환·숫자 표시·행 필터만 수행한다. 이동은 선택 기간 내 최대 5출전, 누적은 선택 기간 시작부터다.
- 상대팀·날짜·유효 지표 필터는 표시 필터다. 필터 후 통계를 재집계하지 않으며 이를 화면에 표시한다. 재집계 기간은 기존 window API로 변경한다.
- 날짜·DH·gameId로 경기를 구분하고 클릭/Enter/Space로 동일 ID 행에 포커스·선택 표시한다. 긴 상대 이름은 축 대신 tooltip과 표에서 제공하며 축에는 날짜와 DH를 제한된 개수로 표시한다.
- 원·사각·삼각과 실선·점선으로 색상 외 구분을 제공한다. 0은 유효 점, null/비유한 값은 N/A 및 끊긴 선으로 처리한다. 초기 1–4출전과 작은 PA/BF/outs의 불안정성을 안내한다.
- DEMO 상세 API에 exportPolicy를 추가한다. canonical synthetic store만 받는 기존 서버 경계를 유지하며 DEMO 자체 저작 라이선스만 내보내기를 허용한다. 외부 라이선스 adapter는 미구현이며 향후 연결 시 서버가 승인된 source license의 exportAllowed를 검증해야 한다. UI는 demo 또는 명시적인 exportAllowed=true 외에는 버튼·다운로드를 차단한다.
- CSV는 화면과 동일한 필터 행, 경기별 지표 전체와 선택 지표 누적/이동 값, 출처·inputRef·기준일·시즌·대회·라이선스를 제공한다. CSV 수식 시작 문자를 escape한다. 저장 스키마 변경은 없고 기존 API 필드는 유지한다.

## ADR-025 · 채택 · DEMO 화면 QA와 검색 비노출 (2026-11-03)

- 공개 DEMO는 모든 페이지에 noindex/nofollow를 적용한다. robots는 비노출 지시를 읽도록 공개 경로 수집을 허용하고 관리자/API는 제외한다. sitemap은 빈 목록이다. 접근 제어 수단으로 간주하지 않는다.
- canonical은 공개 페이지의 필터 없는 경로다. 배포 원점은 SITE_URL로 설정하며 미설정 시 로컬 미리보기 주소다. 실제 도메인은 미확정이다.
- 표본 기반 신뢰도와 예측 정확도를 구분하고 공식 기록이 아닌 합성 DEMO·모델 버전·결측 한계를 소개와 공통 설명 dialog에 공개한다.
- 개인정보/데이터 이용 안내는 출시 전 초안이다. 처리자·로그 정책·연락처·권리 검수 확정은 공개 배포 전 조건이다.

## ADR: 관리자 접근 (채택, 2026-11-03)

P0는 패키지 설치와 외부 계정 연동 없이 Node crypto 기반으로 사전 발급 관리자 capability를 15분 HMAC 서명 세션으로 교환한다. PUBLIC은 세션이 없고 ADMIN은 서버가 검증한 고정 작업자 ID만 가진다. 브라우저 입력 역할/작업자 ID/라이선스는 신뢰하지 않는다. 기본 비밀번호·토큰·서명 키는 없다. 설정이 비면 거부한다. 토큰은 SHA-256 해시만 설정하며 서명 키와 분리한다. 세션은 Secure/HttpOnly/SameSite=Strict이며 로그아웃은 쿠키를 제거한다. 전체 세션 철회는 서명 키 교체로 수행한다. 개인별 다중 관리자·MFA·개별 세션 철회가 필요한 단계에서는 조직 IdP로 전환한다 (제안).

Next 16의 proxy가 /admin 및 /api/admin을 선검사하며 페이지와 모든 handler가 다시 검사한다. ADMIN_ORIGIN은 공개 사이트 origin과 분리된 내부 HTTPS 주소여야 한다. **origin/Host 검사는 네트워크 ACL이 아니다.** 운영 ingress에서 관리자 host를 VPN/사설망/허용 IP에만 라우팅하고 공개 host의 /admin 및 /api/admin은 403으로 차단해야 한다. 앱 시작 명령은 loopback에 바인딩한다. 헤더로 신뢰할 수 있는 원격 IP를 추측하지 않는다.

로그인 전체 5회/분, 관리자 작업자별 60회/분의 단일 프로세스 제한을 적용한다. 다중 인스턴스 배포는 ingress 공유 rate limit이 필요하다. 변경 요청은 정확한 내부 Origin 및 세션을 요구한다. 전달 Host/IP 헤더는 인증 근거로 사용하지 않는다.

감사 로그는 .demo/audit/events.jsonl에 작업자/시각/동작/배치 ID를 별도로 append한다. 요청 본문·토큰을 기록하지 않는다. 신뢰 가능한 IP 제공 계약이 없어 IP는 null로 기록한다. 파일은 불변 저장소가 아니며 운영 실데이터 도입 전 별도 WORM/중앙 수집 저장소와 보존 정책이 필요하다. 요청/완료 이벤트를 구분하며 완료 로그 실패는 이미 반영된 작업을 취소하지 않으므로 상태 확인이 필요하다.

## ADR: 로컬 DEMO 운영 관측 (채택 / 2026-11-03）

운영 도구와 독립된 순수 경고 규칙과 AlertAdapter를 사용한다. 기본 adapter는 집계만 구조화 로그에 기록한다. 기존 관리자 세션을 재사용하고 외부 수집·구독 인프라·스케줄러는 추가하지 않는다. 게시 파이프라인 run에 optional durationMs를 추가하며 이전 상태는 null로 읽는 가산 마이그레이션을 적용한다. 역할·시즌·대회·window·알고리즘이 같은 이전 게시 revision만 점수 분포 기준선으로 사용한다. 임계값은 DEMO 운영 초기값이며 실제 서비스 SLA를 뜻하지 않는다.


## ADR-PERF-01 · 채택 · 대량 DEMO 조회와 오프라인 사전 계산 (2026-11-03)

- 기본 150명 fixture는 유지하고 `DEMO_PROFILE=performance`에서 별도 결정적 600명 fixture를 사용한다. 공식 기록이나 외부 이미지 없이 검증한다. 승인되지 않은 파일 ingest 허용 범위를 넓히지 않는다.
- 홈 기세 계산을 public request에서 제거한다. `db:seed` 별도 프로세스가 역할/기간별 배치를 계산하고, fixture 및 `demo_home_snapshot`을 같은 SQLite 트랜잭션으로 교체한다. snapshot이 없거나 release hash가 다르면 503으로 실패한다. 새 테이블과 release_hash 열은 seed의 additive migration으로 준비한다.
- 모델 기본 trace/hash는 유지한다. 홈 projection은 사용하지 않는 입력 hash만 생략한다. 배치 scorer는 소유한 행 복제본을 freeze하고 동일 release/cutoff의 행 검증을 재사용한다. 선수별 메타데이터 검증과 역할 모델을 유지한다.
- 디렉터리 집계는 immutable fixture별 WeakMap에 기간별로 보관한다. 검색어별 무제한 캐시는 만들지 않는다. SQLite inode/size/mtime/ctime 변경과 파일 게시/rollback은 공개 상태를 invalidate한다. 파일 파이프라인 권한 검사는 캐시 조회 전에 매번 실행한다.
- 파일 게시 재계산은 선수 단위 cooperative batch와 잠금 충돌의 제한 재시도를 사용한다. 단일 선수 계산 및 JSON 직렬화까지 비차단임을 보장하지 않는다. 대량 파일 ingest의 무제한 운영 승인을 뜻하지 않는다.
- PostgreSQL 배치 범위 랭킹 인덱스는 additive migration으로 준비한다. 실제 PostgreSQL projector, EXPLAIN ANALYZE 검증과 호스팅 선택은 미완료이며 DEMO 수치를 그 결과로 대체하지 않는다.

## ADR-TEST-01 · 채택 · 비밀 없는 통합 검증 (2026-11-03)

기존 Vitest/Playwright/axe와 Node inspector를 재사용한다. 설치 금지 범위에서 새로운 coverage provider를 추가하지 않고 핵심 파일별 named-function coverage 85%를 강제한다. 이는 line/branch coverage와 구별한다. CI migration은 disposable PostgreSQL의 고유 스키마에서 실제 SQL을 적용한다. production public E2E와 임시 인증을 쓰는 admin E2E를 순차 실행한다. Prisma CLI는 미설치이므로 설정은 의존성 없는 객체로 유지하며 SQL/schema drift 검증은 미구현이다.

## ADR-DEPLOY-01 · 채택 / 제안 구분 · 2026-11-03

채택: Render Docker 배포 구성, Node 버전 고정, 환경별 서비스 분리, 배포 DEMO 관리자 차단, canonical SQLite schema/hash 검증과 readiness, maintenance 게시 차단. 데이터 계약 승인 없이 실제 PostgreSQL 데이터를 공개 composition에 연결하지 않는다. 배포 로그는 stdout만 사용하며 Render 플랜 보존 기간을 따른다. URL 미발급은 `.invalid` placeholder로 표시한다.

제안: Neon PostgreSQL 17 별도 DEMO 프로젝트, SQL checksum ledger deploy(Prisma와 혼용 금지), 일간 암호화 백업 7일, RPO 24시간/RTO 60분. 도구·계정·비용 승인·복원 측정 전 운영 채택 완료로 간주하지 않는다. 자세한 절차는 DEPLOY_RUNBOOK.md를 따른다.
