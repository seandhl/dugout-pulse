# 화면 명세 v1

기준일: 2026-11-03 (Asia/Seoul). ADR-009 채택 계약. 구현/스크린샷/접근성·브라우저 검수는 아직 없다. [PRD](PRD.md)의 7개 화면을 구체화하며 숫자·기간·ID는 [데이터 사전](DATA_DICTIONARY.md), 응답·오류는 [API 계약](API_CONTRACT.md)을 따른다. DEMO 개발 전용이며 문서 작성이 출시 승인은 아니다.

## 1. 공통 레이아웃·URL·조건

- 360~767px 모바일: 1열, 16px 좌우 여백, 상단 서비스명/메뉴 버튼, 본문 검색·필터·카드 순서. 768px 이상 데스크톱: 상단 텍스트 내비게이션, 최대 본문 1200px, 필터 좌측/요약 우측 또는 2열 상세. 전체 페이지 가로 스크롤 금지. 기록 표만 이름 있는 내부 가로 스크롤 영역을 사용한다.
- 내비게이션은 홈 `/`, 선수 검색 `/players`, 랭킹 `/rankings`, 비교 `/compare`, 소개 `/about`. 관리자 `/admin` 별도 진입. 텍스트/자체 도형을 사용하고 무권한 구단 로고·선수 사진을 넣지 않는다.
- 모든 데이터 페이지 상단과 독립 카드/비교 패널에 **`DEMO · 가상 데이터`**, 시즌·`정규시즌`/`포스트시즌`, 평가 역할을 직접 표시한다. meta.mode=APPROVED는 별도 승인 후 `승인 데이터`로 표시하며 공식 KBO 인증으로 표현하지 않는다. mode를 이용자 토글로 제공하지 않는다.
- 상단 데이터 상태: `데이터 기준 2026-11-01 21:00 KST`(meta.asOf), `마지막 성공 반영 ... KST`(lastSuccessfulSyncAt), 출처명/출처 보기 링크. DEMO에서는 `가상 fixture 게시 · 외부 동기화 아님`. importedAt은 출처 상세에서 별도 제공한다. 요청 cutoff가 다르면 `조회 기준 ... KST`를 함께 표시한다. 상대 날짜만 쓰지 않는다.
- URL 쿼리는 API와 같은 season/competition/role/teamId/cutoffAt/releaseId를 사용한다. 목록은 q/membership/sort, 통계는 window/n, 비교는 playerIds도 저장한다. cursor는 페이지 이동 API에만 사용하고 공유 URL에는 넣지 않는다. 목록 위치는 브라우저 history state에 저장하고 새로고침은 첫 20명부터 복원한다.
- 기본 시즌은 서버가 제공하는 최신 공개 시즌, 대회는 regular, 목록은 appeared/name_asc/20명이다. 홈·랭킹 role은 UI 기본 batter이며 role 전환은 명시 동작이다. 상세 첫 진입은 availableRoles의 batter→starter→reliever 순서로 선택하고, 없으면 listedRoles의 같은 순서, 둘 다 없으면 역할 선택 안내만 표시한다. 이미 URL에 role이 있으면 자동 교체하지 않는다.
- 필터 적용/검색 제출은 URL history push, 첫 응답 releaseId 고정은 replace로 반영한다. 뒤로/앞으로 가기는 URL 조건과 완료된 결과를 복원한다. 시즌·대회 변경은 release/cursor/이전 cutoff를 제거하고 새 활성 배치 조회, 팀/role 변경은 같은 시즌·대회 release 유지 및 cursor 초기화. 비교 선수는 유지하되 새 scope에 없으면 오류 안내한다. 기본값 초기화는 시즌/대회는 유지하고 검색·팀·등록·정렬을 기본값으로 되돌린다.
- 일반 화면에 임의 cutoff 입력 UI는 MVP 제외지만 공유 URL의 유효 cutoff를 그대로 반영한다. 잘못된 URL은 오류 원인과 `기본 조건으로 보기` 버튼을 제공하며 조용히 조건을 변경하지 않는다. 410이면 기존 결과를 지우고 `데이터 버전이 더 이상 제공되지 않습니다`와 `최신 데이터 보기`를 제공한다. 버튼 클릭 때만 release/cursor/cutoff를 제거한다.
- 같은 화면의 모든 통계·기세·목록·비교는 동일 releaseId로 조회한다. 새 게시를 발견해도 화면 일부를 자동 교체하지 않는다. `새 데이터 보기`를 누르면 전체 조건을 한 번에 새 release로 갱신한다.

## 2. 공통 상호작용·접근성

| 요소 | 클릭/터치 | 키보드·보조기술 |
| --- | --- | --- |
| 내비게이션·선수명 | 실제 링크, 상세 URL에 조건/release 유지 | Tab/Shift+Tab, Enter. 현재 메뉴 aria-current=page. 새 탭·링크 복사 가능 |
| 모바일 메뉴/필터 | 버튼 열기, 닫기/적용/초기화. 적용 전 값을 결과에 반영하지 않음 | aria-expanded/controls, dialog 라벨, 열 때 첫 필드 초점, Tab trap, Escape 닫고 트리거로 복귀 |
| 검색 | 명시 제출(버튼/Enter), 입력마다 네트워크 호출하지 않음 | label+도움말+100자 제한, Enter 제출. 결과 수는 aria-live=polite, 입력 초점 보존 |
| 역할·윈도 선택 | URL과 결과 갱신 | 라디오 그룹/네이티브 select 우선. 탭 UI면 좌우 화살표/Home/End 및 aria-selected, 선택과 패널 연결 |
| 표 정렬 | 허용된 정렬 버튼 클릭 | 버튼 이름에 방향, th aria-sort. 정렬 후 버튼 초점 유지, 변경 안내 |
| 더 보기 | 다음 cursor 20명 추가, 중복 클릭 방지 | 실제 button, aria-busy, 완료 후 추가 결과 첫 링크로 초점 이동·추가/전체 수 안내. 실패 시 버튼 초점과 기존 목록 보존 |
| 출처·계산 설명 | 기본 인라인 details 열기, 필수 DEMO/as-of는 접지 않음 | summary Enter/Space. 강제 modal 사용 안 함. 닫아도 읽기 위치 보존 |
| 비교 담기/제거 | 최대 2명, 이름과 role 표시 | 버튼 accessible name에 선수명 포함. 추가/제거 aria-live, 제거 후 이웃 버튼 또는 선택 필드로 초점 이동 |
| 재시도 | 같은 조건/release로 다시 조회 | 실제 button, 진행 중 중복 실행 금지, 성공/실패 상태를 live 영역에서 안내 |

문서 lang=ko, 페이지마다 유일한 h1, skip-to-main, main/nav landmark, 필드마다 지속 label, focus-visible 테두리와 논리적 DOM 순서. 본문 텍스트 대비 ≥4.5:1, 큰 글자/컴포넌트·초점 ≥3:1, 터치 대상 최소 44×44 CSS px. 점수 상승/하락은 색+`상승`/`하락`/부호로 함께 표현하며 색만으로 전달하지 않는다. 200% 확대·320px reflow에서도 조작 가능, 360px 전체 가로 넘침 0. 모션은 prefers-reduced-motion을 따른다.

그래프에는 제목·축 단위·표본·기간·대체 표가 항상 있다. SVG/canvas hover tooltip만으로 수치를 제공하지 않는다. 날짜별 수치는 키보드로 접근 가능한 표에서 동일하게 읽는다. 결측은 선을 끊고 `자료 없음`, 0은 실제 기준선 점으로 표현한다. 비교 차트는 같은 축/단위/기간을 사용하고 역할·윈도가 다르면 겹치지 않는다. 스크린리더용 수치도 화면과 같은 반올림을 사용한다.

## 3. 화면별 정상·반응형 동작

### 홈 `/`

순서: 서비스 목적/비예측 안내 → DEMO·출처/기준일 → 시즌·대회·역할 → 역할별 기세 요약 → 선수 검색 링크·방법 설명.

- 기세는 `/rankings`에서 해당 역할의 앞 3명만 사용한다. MVP에 실제 예측·승률·임의 인기순을 넣지 않는다. 모델 pending이면 `모델 미확정`과 검색 진입을 보여주며 순위 카드·숫자를 만들지 않는다.
- 카드에 선수명 링크, 역할, 점수/산출 상태, 현재/직전 표본, 사용 기간, 마지막 출전 경과일, 출처 링크, 비교 담기를 둔다. 데스크톱 3열/모바일 1열이며 순서 동일.
- 다른 역할 선택 시 해당 모델·해당 경기만 다시 읽고 이전 역할 점수를 새 역할 칸에 보여주지 않는다. 키보드 역할 그룹→선수 링크→비교 버튼 순서.

### 선수 검색 `/players`

순서: h1 → 이름 검색 → 시즌/대회/팀/역할/시즌 출전·기준일 등록·전체 선택 → 결과 수/조건 요약 → 선수 목록 → 더 보기.

- 기본 `시즌 출전`은 선택 scope의 확정 출전 선수다. `기준일 등록`은 등록 snapshot의 선수로 0출전도 나타난다. 과거 시즌에 `현재 등록`이라고 쓰지 않는다. snapshot 날짜를 옆에 표시한다. unknown은 미등록으로 분류하지 않는다.
- role 선택 시 appeared는 실제 출전 role, registered/all은 listedRoles 기준이라는 도움말을 직접 제공한다. 전체 선수의 팀 필터는 snapshot 소속, 출전 목록 팀은 출전 당시 소속임을 라벨로 구분한다.
- 데스크톱 표: 선수명·소개 역할·팀(기준 명시)·등록 상태/기준일·시즌 출전 수. 모바일은 동일 필드를 카드 한 장에 표시한다. 팀이 여러 개면 출전 팀 목록 텍스트와 `이적 포함`을 표시하고 현재팀이라고 단정하지 않는다. 이를 위해 출전 팀 목록은 gamelog를 선수별 N+1 호출하지 않고 목록 Player의 seasonTeams 필드로 받는다(API 계약 참조).
- 이름순 오름/내림만 지원한다. 동명이인은 팀/role/playerId 축약 보조 정보로 구분하되 클릭 URL은 전체 playerId를 쓴다. 이름/등번호 검색으로 ID를 만들지 않는다.

### 선수 상세 `/players/:id`

순서: 선수명·보조 ID/등록 → 역할 선택 → 기세 요약 → 시즌/최근/직전 통계 → 추이 그래프와 대체 표 → 경기 로그 → 출처·모델 설명 → 비교 담기.

- identity는 `/players/:id`, 통계는 `/stats`, 점수는 `/momentum`, 기록은 `/gamelog`를 동일 scope로 사용한다. 역할 선택을 바꿔도 playerId는 유지한다. 투타 겸업/선발·불펜 전환을 독립 패널로 보여주며 기록을 합치지 않는다.
- 상단에 `선발 평가 · GS=1인 등판만` 또는 `불펜 평가 · GS=0인 등판만`, 타자는 `타격 출전 기준`을 명시한다. 직업/주역할이 아니라 평가 조건이다.
- 통계 기본 recent, N은 통계 조회 10/5/10. 시즌 합계 전환 가능. MVP의 임의 N 입력은 제공하지 않지만 유효 URL n은 반영하고 `최근 N회`를 표시한다. `최근 N팀 경기`라고 쓰지 않는다. 최근/직전 시작·끝·availableN/requestedN을 보여주고 모델 N은 별도 표시한다.
- 타자: G/PA/AB/H/2B/3B/HR/BB/HBP/IBB/SO/SF/SAC/R/RBI/SB/CS/TB와 AVG/OBP/SLG/OPS. 선발·불펜: 등판 수/BF/아웃 수/분수 이닝/H/ER/R/BB/IBB/HBP/SO/HR/NP/GS/SV/HLD와 ERA/WHIP/K/9/BB/9. 모바일 핵심 수치 먼저, 나머지는 `전체 기록` details로 제공하되 필드를 생략하지 않는다.
- `NP 미제공`, `— · 분모 0`, `— · 원천 누락`, `기록 없음`을 구분한다. 부분 합계는 `확인된 3/5경기 합계`라는 별도 보조값으로만 표시한다.
- 타자 차트는 출전별 PA/H/HR와 선택 구간 OPS, 선발은 등판별 아웃/ER/SO와 구간 ERA, 불펜은 등판별 아웃/ER와 최근 14일 사용량. 이동 구간 비율은 그 시점까지의 실제 N출전에서 다시 계산하며 결측/분모0을 0으로 그리지 않는다.
- 차트의 이동 구간을 위해 로그를 불완전하게 받았으면 그 부분은 `추가 기록 필요`로 표시하고 서버 통계나 충분한 로그가 없는데 추정 그래프를 만들지 않는다. 더 보기로 받은 로그 역시 같은 release여야 한다.
- 마지막 출전일·경과일은 완료일/cutoff KST 기준. `최근 출전 이후 12일 · 데이터 기준일 기준`이라고 쓰고 부상/휴식 이유를 추측하지 않는다. 불펜 7일/14일 아웃·연속 등판일은 별도 달력 사용량이다.
- 데스크톱 프로필/기세 2열, 아래 통계/표. 모바일 동일 DOM 1열, 경기 표는 식별 열 고정+영역 가로 스크롤(aria-label, 키보드 초점, 스크롤 안내). 날짜·DH 회차·경기 ID 링크/텍스트·role·GS·정정 revision을 확인 가능하게 한다. 중단/무효는 유효 경기표에 0기록으로 넣지 않으며 출처 설명에 제외 정책을 제공한다.

### 랭킹 `/rankings`

순서: h1 → 시즌/대회/팀/역할 → 모델 버전·N·최소 표본·동점 설명 → 순위 표 → 제외 상태 요약·선수 탐색.

- raw score 내림차순, 실제 동점 1·1·3. 표시 반올림 값이 같아도 원값이 다르면 순위 차이를 유지하고 도움말로 알린다. ID tie-break는 순위 숫자를 바꾸지 않는다. 더 보기에도 전체 순위 유지.
- 행: 순위·선수 링크·점수·변화·최근/직전 표본·기간·마지막 출전·비교 담기. 점수/변화 결측을 `0` 또는 `-0.0`으로 표시하지 않는다. 모바일 카드도 같은 필드를 제공한다.
- 표본 부족/데이터 누락/미출전은 순위 밖 상태 요약으로 구분하며 최하위/0점으로 섞지 않는다. 모델 pending은 전체 `모델 미확정`, 표본 부족은 `산출 가능한 선수 없음`으로 다르다.
- 정렬 UI는 기세 내림차순만 제공한다. 선수 이름순 탐색은 검색 화면으로 이동한다. 역할 간 통합 순위 버튼은 없다.

### 선수 비교 `/compare`

순서: 공통 조건 → 선택 2슬롯 → 비교 가능 조건/모델 버전 → 나란한 통계·기세 → 동일 축 차트·표 → 출처.

- 0명은 `첫 선수를 선택해 주세요`, 1명은 선택 선수를 유지하고 `같은 역할의 두 번째 선수` 검색 링크. 이때 2명 필수인 `/compare` API를 호출하지 않는다. 2명부터 GET 호출한다. ID 순서는 URL에 고정한다.
- 세 번째 담기는 기존 2명을 덮어쓰지 않고 `최대 2명 · 제거 후 선택` 안내와 제거 버튼을 제공한다. 다른 role 선수 추가는 선택 거부 및 같은 역할 선택 안내. 같은 선수를 다시 담으면 `이미 선택됨` 안내. URL에 3명/중복이 있으면 오류를 보여주고 편집 UI를 유지한다.
- 두 선수는 같은 시즌·대회·평가 역할·팀·cutoff·release·scoreVersion·통계 N을 공유한다. 팀 필터로 한 선수가 0출전이면 0출전 상태를 그대로 표시하고 전체 팀으로 몰래 바꾸지 않는다. 선수별 출전 날짜 범위가 달라도 각각 날짜를 표시하며 최근 N은 선수마다 독립 선택이다.
- 데스크톱 두 선수 열+공통 지표명 열, 모바일 두 선수 열을 유지한 압축 표 또는 지표별 두 값 카드(전체 페이지 가로 넘침 금지). 차트 축·수치 단위를 공유한다. 부분 결측은 해당 수치만 비우고 다른 정상 수치는 유지한다.
- 한쪽 계산 실패는 성공 패널 유지, 실패 패널 이름/사유/재시도. 재시도는 동일 조건 2명 API를 다시 호출하며 로딩은 실패 패널에만 표시, 결과 갱신은 동일 release임을 확인한다. 두 실패는 전체 오류. 역할·버전 충돌은 수치 비교를 막고 조건 수정 링크를 제공한다.

### 소개/출처 `/about`

목적·DEMO/비공식/비예측 안내 → 역할별 계산 정책/버전/표본 → 출처 목록/데이터 기준·마지막 성공 반영 → 기간·정정·결측 설명 → 권리·운영/문의·필수 법적 표시.

- `/meta`와 안전한 정적 설명을 사용한다. 모델 미확정이면 `산식·최소 표본 미확정(P3)`을 쓰고 제안 0~100/10·5·10을 채택 모델인 것처럼 쓰지 않는다. 통계용 N은 확정 계약으로 따로 설명한다.
- sourceId/rightsRecordId/공개 출처명·표기문·publicUrl만 제공, 내부 evidence나 계정/원본 파일 접근 버튼 없음. 로고/사진 권한은 데이터 승인과 다르다고 안내한다.
- 운영 주체/문의 미정이면 개발 미리보기에서 `미정 · 공개 출시 전 필수 확정`을 표시하고 P5 출시를 차단한다. 허위 이메일·가짜 약관 링크를 만들지 않는다.
- 모바일/데스크톱 읽기 폭 최대 72ch. 목차 앵커는 키보드 링크, 링크 이동 시 제목 초점을 제공한다.

### 관리자 `/admin`

이 화면은 공개 API 계약의 인증을 우회하지 않는다. 현재 인증 미구현이므로 기본 접근 거부. 향후 별도 서버 인증 후에만 다음 흐름을 구현한다.

- 인증 확인 중 배치/미리보기 내용을 DOM에도 노출하지 않는다. 미인증은 로그인 안내, 비관리자는 접근 거부(로그인 재시도로 권한을 얻는 것처럼 안내하지 않음). 세션 만료 시 민감 영역을 제거하고 재인증 안내.
- 배치 목록 → fixture 파일 입력 → 검증 결과(행·필드·안전한 원인) → 공개 DTO 미리보기 → **게시 확인 dialog** → 원자 게시 결과. 입력은 최대 5MiB/50,000행, DEMO 가상 fixture만. 승인되지 않은 CSV/API 수집·실제 mode 전환 UI 없음.
- 미리보기는 DEMO·출처·as-of·시즌·대회·표본·권리 검사 상태·행 수·대상 release revision을 보여준다. 오류 하나라도 있으면 게시 버튼 disabled와 사유. 검증 실패는 기존 공개 배치 유지.
- 게시 dialog에는 대상 scope/배치/현재 revision을 표시하고 `이 배치를 게시` 버튼에 초기 초점을 주지 않는다(취소 또는 제목에 초점). Enter로 파일 선택 직후 게시하지 않는다. 실행 시 서버 Idempotency-Key/expectedRevision, 세션/역할/CSRF/현재 권리 재검사. UI 잠금만으로 안전을 주장하지 않는다.
- 409 동시 변경이면 현재 공개 배치 유지·새 revision 재조회·미리보기 재확인 후 명시 재시도. 네트워크 불명확 실패는 동일 idempotency key로 상태 확인/재시도하여 이중 게시 방지.
- 복구는 이전 배치/권리/모델 유효성 재검사 후 새 release 게시이며 원본 수정이 아니다. 대상/변경 범위를 dialog에서 확인한다. 현재 권리 철회 배치 복구 금지. 감사 목록은 허용된 관리자에게만 안전한 동작·대상·시각·결과 표시.
- 데스크톱 배치 목록과 미리보기 2열, 모바일 순차 단계. 표/오류 행 링크는 키보드 접근 가능, dialog Escape 취소·초점 복귀. 게시 성공은 live 안내와 새 공개 화면 링크, 실패는 기존 공개 링크 유지.

## 4. 상태 매트릭스

모든 요청은 완료/실패/취소 경로를 갖는다. 스켈레톤 aria-hidden, 결과 영역 aria-busy, 상태 설명 텍스트. 조건 변경 중 이전 결과를 잠깐 유지하면 `이전 조건 결과 · 갱신 중`을 붙이고 비교 담기 등 해당 결과 동작을 잠근다. 늦게 도착한 이전 요청은 취소/sequence 검사로 새 화면에 덮어쓰지 않는다. 15초 무응답은 요청 중단 후 시간 초과 안내·재시도; 서버 성공을 추정하지 않는다.

meta.dataStatus=no_published_data는 서버 데이터 미게시 상태이며 검색 0명과 다르다. 오래된 데이터는 기준일/마지막 성공 반영 시각을 직접 보여준다. 공급 갱신 SLA가 없으므로 `실시간`/`동기화 정상`/임의 N시간 기준 지연 배지를 만들지 않는다. 명시적인 실패 응답이 있으면 실패를 표시하되 마지막 성공 시각은 유지한다.

APPROVED 응답은 오프라인 권리 확인 불가·410/철회가 오면 메모리 수치도 즉시 제거한다. 수동 다운로드·영속 캐시·Service Worker offline 통계 제공은 MVP 범위 밖이다. 운영 장애를 실제 수치로 채우지 않는다.
