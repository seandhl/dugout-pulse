# 로드맵

단계 의존성: **P0 → P1 → P2 → P3 → P4 → P5**. 각 수락 기준을 확인한 후 다음 단계로 진행한다. 실제 데이터 승인은 별도 조건이며 데모 개발을 막지 않는다.

| 단계 | 범위 | 의존성 | 수락 기준 |
| --- | --- | --- | --- |
| P0 기반 문서 | 환경·Git 진단, 범위·규칙·결정·가정 기록 | 없음 | README, AGENTS, ROADMAP, DECISIONS, ASSUMPTIONS 실제 생성; 진단·첫 확인 명령 보고; 외부 수집 없음 |
| P1 앱 기반 | 독립 Git 경계, 런타임 고정, 패키지·lockfile, 한국어 기본 화면, 검사 스크립트 | P0 완료 | 독립 Git 경계 확인; 설치·개발 실행 명령 검증; TypeScript strict·lint·build 통과; DEMO 표시; 로딩·오류·빈 화면·오프라인 기본 상태 확인 |

| P3 기세 모델 | 타자·선발·불펜 별도 계산, 설명·표본·휴식 처리 | P2 완료 | 역할별 산식·모델 버전·윈도·최소 표본을 ADR에 명시; 경계값·누락·역할 전환·휴식 테스트; 같은 입력에 같은 결과; 데모 점수를 공식 지표로 표현하지 않음 |

## 단계 운영

각 단계 종료 보고는 수행 작업, 변경 파일, 테스트 명령과 결과, 화면 확인 방법, 알려진 제한, 다음 단계 준비를 포함한다. 미충족 기준과 차단 사유를 남기고 다음 단계 완료를 선언하지 않는다.

P1 기술 기본 제안은 TypeScript strict + Next.js App Router + pnpm 단일 앱이다. 현재 설치된 패키지는 없으며 버전은 P1에서 호환성과 지원 상태를 확인한 후 고정한다. 초기 fixture는 파일로 관리하고 별도 DB·계정·유료 인프라를 도입하지 않는다.

## 아키텍처 결정 반영 (2026-11-03)

[ADR-008](DECISIONS.md)과 [ARCHITECTURE](ARCHITECTURE.md)에 따라 단일 Next.js 앱·Node 컨테이너 기본 배포를 채택한다. 위 초기 기술 제안의 구조 선택은 대체되며 버전 조회와 설치 검증을 구분한다. fixture 입력 우선은 유지하고, P2 이후 영속 배치·게시·복구·감사는 PostgreSQL + Prisma로 구현한다. P0에서는 패키지/DB 설치·실행 없이 문서만 작성한다. P1 앱 기반 검증, P2 migration·실제 DB 계약 테스트, P4 동시 게시·복구·권한 통합/E2E 검증을 각 기존 수락 기준에 포함한다. 단계 완료 판정은 변경하지 않는다.
